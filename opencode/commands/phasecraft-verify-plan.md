Load the `phasecraft` skill and perform only Verify Plan for `$ARGUMENTS`. Run the `verify-plan` preflight. Independently compare the current plan to user decisions, evidence, roadmap requirements, repository state, and risk records.

Run `knowledge-check`. Require every requirement to map to observable checks, every task to valid evidence and a commit group, every risk to mitigation work, and every proposed edit to have a verified before state. Confirm that each technical change declares type, database impact, API impact, and flow impact; includes accurate language-tagged before/proposed code plus a concrete expected-result snapshot; and provides migration plus rollback detail whenever database impact is not `none`. Database expected results must show realistic complete persisted documents/config/indexes, and API changes must show exact request/response or payload shape. Treat vague placeholders or snippets insufficient to reconstruct signatures, control branches, data shape, output, error handling, or side effects as blocking findings.

Independently trace each non-`none` `Flow impact` through the repository and require it to reference a valid `F-*` entry. Verify every `Application Flows` entry names the real surface, entry point, owning phase, evidence-backed before behavior, and proposed after behavior. Mermaid diagrams must use separate BEFORE/AFTER subgraphs without crossover edges, expose business decisions and fallback, and remain readable rather than enumerating every low-level helper. Require a `changes` mapping for every surgically changed AFTER node and verify each phase, file, symbol, and edit intent against repository evidence. For estimate flows, verify tariff API ordering, flat eligibility, complete regular/flat discount stages, final-price comparison, tie policy, selected SLA, and fallback. For creation flows, verify persistence before external side effects, both boolean classifications, retry/pay-later reuse, payload mapping, errors, and unchanged excluded paths. Reject internal validator/index diagrams presented as the feature flow, decorative diagrams, invented paths, task-only diagrams, or unmapped application changes.

Check dependencies, negative cases, boundaries, stale hashes, unrelated scope, dirty baseline overlap, and human-only checks. Manual checks must be independently executable with preconditions, exact action/command, safe environment/data, expected observations, failure criteria, and cleanup where needed. Run the restricted Markdown validator; inspect `plan.html` for visible syntax-token spans, concrete expected-result panels, successfully rendered Mermaid BEFORE/AFTER application flows, surgical change-point tables, database/API/rollback panels, one full-width row per manual check, complete evidence claim/provenance/status references, no missing-detail placeholders, and the correct HTML source hash.

Write `PLAN-VERIFICATION.md` with findings ordered by severity. Transition to `plan_verified` only when no blocking finding remains; otherwise leave `plan_draft`. Never edit application source or silently repair the planner's conclusions.

Run `handoff-list --all` and read the latest planner plus all prior auditor handoffs before auditing. Before every return, invoke `handoff-write --agent phasecraft-plan-auditor` with findings, checks, state/revision, blockers, and exact next action; never allocate `H-NNN.md` manually.
